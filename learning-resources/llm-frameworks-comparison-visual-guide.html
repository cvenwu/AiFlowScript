LLM 应用框架速查图

四个工具，四个层级。

它们不是互相替代的同类产品，而是分别站在「数据结构」「知识检索」「应用编排」「状态机工作流」四个层级。 最简单的记忆方式：Pydantic 管格式，LlamaIndex 管知识，LangChain 管串联，LangGraph 管复杂流程。

Pydantic LlamaIndex LangChain LangGraph
Layer model
LangGraph 有状态、多节点、可循环的 Agent 工作流
LangChain 把 LLM、Prompt、工具、API、检索器串起来
LlamaIndex 读取外部资料，切分、索引、检索、RAG 问答
Pydantic 定义输入、输出、业务对象的数据结构与校验
图中越往下越基础，越往上越接近完整应用。实际项目可以只用其中一个，也可以组合使用。

每个工具的主战场

把它们想成一家公司里的四种角色：数据合同、知识管理员、应用集成工程师、流程导演。

P

Pydantic

数据结构与类型校验。

  • 定义字段、类型、默认值
  • 校验 JSON / API 入参
  • 约束 LLM 结构化输出
L

LlamaIndex

外部知识接入与 RAG。

  • 读取 PDF、网页、数据库
  • 切分、索引、向量检索
  • 基于私有资料回答问题
C

LangChain

LLM 应用编排胶水。

  • 连接模型、Prompt、工具
  • 封装 Retriever 与 Agent
  • 调用搜索、数据库、外部 API
G

LangGraph

复杂 Agent 状态机。

  • 节点、边、条件分支
  • 循环、回退、中断、恢复
  • 多 Agent 与人工审批流程

一个 AI 助理的完整链路

如果把四者放进同一个项目，它们通常这样分工。

01 / STRUCTURE

先定义数据长什么样

用 Pydantic 规定用户请求、工具参数、最终回答的字段和类型。

02 / KNOWLEDGE

再接入企业资料

用 LlamaIndex 把文档、网页、数据库变成可检索的知识索引。

03 / TOOLS

然后串起模型和工具

用 LangChain 组织 Prompt、LLM、检索器、搜索、数据库等调用。

04 / CONTROL

最后控制复杂流程

用 LangGraph 让 Agent 能规划、执行、反思、重试和等待人工确认。

我该用哪个？

点击左侧场景，右侧会给出推荐组合。

Recommended

优先用 Pydantic

它负责把「不稳定的自然语言输出」变成「稳定的结构化对象」。如果你只是需要字段校验、JSON Schema、结构化输出，不需要上 LlamaIndex / LangChain / LangGraph。

典型组合：Pydantic + OpenAI / Claude structured output
关键词：BaseModel、Field、类型校验、JSON Schema
不要误用：不要拿它做文档检索或 Agent 流程控制

一句话对照表

如果只记一张表，就记这张。

工具 它管什么 不主要管什么 类比
Pydantic 数据模型、类型校验、结构化输出 不负责检索文档，不负责 Agent 编排 合同模板 / 表单校验器
LlamaIndex 数据接入、索引、检索、RAG 问答 不专注复杂业务流程状态机 图书馆管理员 / 知识库引擎
LangChain LLM、Prompt、工具、外部 API 的编排 不如 LangGraph 擅长复杂循环状态控制 应用集成胶水 / 调度脚本
LangGraph 多节点、有状态、可循环的 Agent 工作流 不替代底层数据校验和知识索引 流程导演 / 状态机引擎

常见项目组合

现实中它们经常组合使用，而不是四选一。

普通 RAG 知识库

员工问制度、客服问手册、研发问文档。

LlamaIndex Pydantic

会调用工具的助手

既能查资料，也能调用搜索、数据库、内部系统。

LangChain Pydantic

复杂自动化 Agent

需要规划、执行、重试、人工审批、长期状态。

LangGraph LangChain Pydantic
结论：Pydantic 是地基，LlamaIndex 是知识层，LangChain 是连接层，LangGraph 是复杂流程控制层。
