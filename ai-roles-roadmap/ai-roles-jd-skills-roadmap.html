共享 能力底座 · L0

无论目标是哪条岗位分支，下面 5 项都是 7 个岗位 JD 中反复出现的共同地基。先把 L0 打牢，再分流到主干。

L0 · 01

Python

每条 JD 都出现的"绝对硬通货"。能写后端服务、能调 LLM API、能跑数据脚本。

L0 · 02

LLM 第一性原理

Token、context、注意力、采样、temperature；理解能力边界（幻觉、时效、推理成本）。

L0 · 03

工程素养 + Linux / Git / 容器

能调试生产故障、读源码、用 Docker 跑环境。算法岗也跑不掉。

L0 · 04

Evals 思维

能定义指标、做回归、归因 Bad Case。从 Anthropic 到小红书 JD 都点名。

L0 · 05

用过头部 AI 产品

Claude Code / Cursor / Codex / Manus 重度使用。NVIDIA、DeepSeek、字节都写进 JD。

// 05

学习路线 · 底座 + 分支

不绑定具体周数（节奏因人而异）；分四阶段推进，每阶段都有"完成的验证标准"。

// PHASE 0公共底座
目标：把 L0 五项打到"能讲清 + 能写代码"。
必做：跑通 LLM API 调用、手写最小 Agent 循环（while + 1 个工具，禁用框架）、能解释 Transformer / 注意力 / 采样、自己定义一个评测脚本对 Agent 跑回归、重度使用一次 Claude Code 或 Cursor 完成一个真实任务。
验证：能在 10 分钟内白板讲清"为什么 LLM 需要 Agent"，并展示一个最小 demo。
// PHASE 1选主干 (A / B / C)
三主干：A 工程（系统/容器/分布式）· B 模型（PyTorch/Transformer/分布式训练）· C 应用（Prompt/RAG/工具编排）。
建议：每主干完成 1 个"中等规模项目"再分流到具体岗位 —— 例如 A 写一个带沙箱与工具调度的 mini agent runtime；B 从零实现 GPT-2 训练并跑通多卡；C 做一个有 RAG + 工具 + Evals 闭环的应用。
验证：项目能讲清"为什么这样设计、踩过哪些坑、怎么衡量好坏"。
// PHASE 2岗位专精
从主干选具体分支：看上面的依赖图谱按 P0 → P1 → P2 顺序补齐。
建议产出：1 个"可在面试讲 30 分钟"的旗舰项目 + 2 个能写进简历的小项目。
验证：能用真实指标讲收益（吞吐 +X%、Bad Case 收敛 Y%、Eval 通过率从 A → B）。
// PHASE 3面试硬化
