AI · 概念澄清

AI harness = 让模型能真正干活的那层工程系统。模型只是 text in → text out，Claude Code/Cursor/Devin 强在外面包的 harness：

  • 运行时：Agent 循环、工具调度、上下文管理、会话压缩、子 agent 派发
  • 评测：基准任务自动跑 + 打分 + 回归（SWE-bench 等）
  • 工程基设：沙箱执行、上下文流水线、可观测性、缓存

核心洞察：后端工程师的差异化优势在 harness（系统设计/并发/状态/健壮性/成本），不在模型调参。路线应「应用层快速入门 → 重仓 harness」，不卷 Transformer 数学。

AI · 路线组织方式三选一
方案说明取舍
A 能力螺旋式原理→应用→harness→评测层叠，主线大项目串起项目连贯、可深聊；前期成就感慢
B 面试驱动逆推从 JD/面试题倒推能力最快出结果；知识易碎
C 双线并行应用线与 harness 线并行两作品；冲刺下易半成品

决策 → A 为主线 + B 为辅助

AI · 阶段 0 + 1

阶段 0（1-1.5 周）

原理：LLM 本质、为何需要 Agent、ReAct、Tool Calling、Prompt 基础。

项目：禁用框架手撸最小 Agent 循环（Python 50 行内，挂计算器工具）。

阶段 1（2 周）

RAG 全链路 + 工具生态 + LangGraph 编排 + 记忆。项目：「文档问答 + 工具增强」Agent 应用，暴露 FastAPI。

→ 用户认可阶段 0；对阶段 1 框架不确定，要求调研 LangGraph 是否最优。

AI · 应用层框架调研（2026）
维度LangGraphOpenAI SDKPydanticAILlamaIndex
零基础学习曲线中低低中
生产/面试热度最高高上升高(RAG)
状态/持久化最强弱中中
类型安全/可测试中中最强中
对学 harness 启发最大中中小
RAG 能力中弱弱最强

结论：主选 LangGraph（状态图=后端主场、是 harness 参照系、面试热度第一）+ PydanticAI 对照学习（类型安全、工具契约参考）+ LlamaIndex 做 RAG。不选 CrewAI/AutoGen（封装太深，不利看穿原理）。

→ 用户认可

AI · 阶段 2 + 3

阶段 2 — Go harness 内核（3 周，重头戏）

Agent 循环引擎 / 工具调度（goroutine 并发）/ 上下文管理+会话压缩 / provider 抽象+流式 / 沙箱执行。子 Agent 派发 → 弹性进阶

阶段 3 — 评测与硬化（2-3 周）

自建 benchmark + LLM-as-judge + trace + token 成本 + 优化对比数据。SWE-bench → 弹性进阶

面试金句：「Go 自研 harness 对标 LangGraph，并发/成本做了 X 优化，eval 从 A 到 B」。
